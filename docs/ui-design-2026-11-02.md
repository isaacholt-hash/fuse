## What FUSE is, for the design

One person's daily tool that routes each request to the cheapest model that can do it and shows what every answer cost and why. Short bursts, dense, calm. The conversation is the hero and the chrome stays quiet (`docs/ui-brief.md` still holds). What is specific to FUSE, and so where the design spends its one bold choice, is the receipt: tier, model, cost and reason beside every answer, and spend against a cap.

## The signature: a ledger margin

Every message has a margin column to its right, 132 px wide, that says who answered and what it cost:

```
┌─ sidebar 248 ─┬──────────── reading column ≤ 68ch ─────────────┬─ margin 132 ─┐
│ ⌁ FUSE        │ Kitchen renovation / Tile budget                │  this thread  │
│ Chat | Code   │                                                 │    $0.1184    │
│ + New chat    │ Here are the three tile quotes…                 │  you · 14:02  │
│ Search        │                                                 │               │
│ Kitchen reno… │ Only Marrakech Tile includes the trim…          │  Sonnet 5.5 ▮▮│
│   Tile budget │   table                                         │    $0.0093    │
│   Grout colour│                                                 │ files + table │
│ Yesterday     ├─────────────────────────────────────────────────┤  1,240 in …   │
│   …           │ [composer]  Auto → Sol ▮▮  Medium  Search  41% ▲│   ≈ $0.006    │
└───────────────┴─────────────────────────────────────────────────┴───────────────┘
```

The column runs unbroken from the thread total in the header ("this thread $0.1184, about $0.03 a message"), past each answer (model and tier glyph, cost, the routing reason, tokens in, out and cached), to the estimate under the composer ("next message ≈ $0.006"), so a thread reads like an account. It replaces the cost badge under each answer; the hover breakdown (cost per part, latency) stays, on the figure. While a model works the margin shows the running tokens and cost and a Stop button; a model switch is a thin divider across both columns ("Switched to GPT-6.1 Sol · full history sent"). Below 900 px the margin folds under its message as one line.

In the Code area the same column carries the session total and time, each step's cost, and "cap left" under the composer. The home screen's lists (waiting for you, going, next scheduled, today) use the same two columns: the thing on the left, its time and money on the right.

## Tokens

Colour. Slate ink on paper, and copper for money and nothing else; the tier bars and the day-cap line are the only copper outside a figure. No blue, no gradients, no shadows except popovers.

| Token | Light | Dark | Use |
| --- | --- | --- | --- |
| paper | `#FAFAF8` | `#151A22` | shell: sidebar, header, composer surround |
| page | `#FFFFFF` | `#1B212B` | reading surface, popovers |
| ink | `#1B2130` | `#E8E9EC` | text, filled controls |
| muted | `#5C6370` | `#9AA1AD` | secondary text, margin |
| rule | `#E3E4E1` | `#2A313D` | borders, dividers, empty tier bars |
| raised | `#F1F1EE` | `#242B37` | chips, hovered rows |
| copper | `#9A4A1A` | `#E0995F` | money, tier bars, cap line |
| error | `#B3261E` | `#F08A80` | errors, deleted lines |
| warning | `#8A5A00` | `#E8B04A` | needs attention, not an error; soft `#F7EFDC` / `#3A3220` |
| success | `#047857` | `#34D399` | paired, scheduled, added lines; soft `#E3F1EC` / `#1D3A34` |
| highlight | `#FBE7A6` | `#5C4621` | search and find hits, behind ink |

Contrast on their backgrounds: ink 16.1, muted 6.1, copper 6.2 (light) and 7.4 (dark), error 6.5, warning 5.9 and success 5.5 (light; added 2026-11-08 from the impeccable audit, values in `src/index.css`). Keep every pair above 4.5.

Type. IBM Plex Sans for everything read and operated; IBM Plex Mono only for code and keyboard hints. Money is sans with tabular figures (`font-variant-numeric: tabular-nums`), weight 500, so the ledger lines up without reading as a terminal. Geist goes.

| Role | Size / line | Notes |
| --- | --- | --- |
| reading | 15 / 1.6 | answers, max 68ch |
| interface | 14 / 1.5 | sidebar, controls, user messages (in muted) |
| margin | 12 / 1.5 | who, why, tokens |
| money | 13, tabular, 500 | copper; 16 for the thread total |
| code | 13 mono | inline and blocks |
| keys | 11 mono | `kbd`, muted, 1 px rule border |

Radius by role, not one value everywhere: 4 px chips, keys and code; 6 px buttons, inputs and rows; 10 px the composer and popovers. A border only around a run card, where it marks a thing that is happening.

Signals. State dots: filled ink = waiting for you; hollow, pulsing = going; hollow in rule colour = done; a bold title = done and unseen. Place: a laptop glyph for this computer, a server glyph with "HULK" for HULK. Tier: a fuse rating of one, two or three bars beside every model name (cheap, balanced, best), in the margin and in the composer chip, so the routing's "why" reads without a tooltip. The logo is a fuse cartridge, end caps in ink and the filament in copper, replacing the bolt.

Words. Sentence case everywhere. No eyebrows, no taglines, no tracked capitals: today every screen opens with one ("A little less friction", "Code and work sessions", "Make yourself at home") and they all go. Section labels say what the group is (a project name, "Yesterday", "Waiting for you"). Empty states say what is true and what to do ("Nothing running. $0.00 spent today."). The composer placeholder is "Ask anything. Auto picks the model." in Chat and "Reply, or type / for commands" in a session.

Motion. One moment: when an answer finishes, its figure settles into the margin and the thread total updates. While a model works the margin shows live tokens and cost. Nothing else moves unless the user moved it, and `prefers-reduced-motion` turns the one moment off.

## What this is not

The default for a developer chat tool would be dark first, Geist or Inter, a blue accent, a cost badge under each answer, caps labels and mono for every small number. Each is replaced above for a reason tied to FUSE: light first because the reading column is the product; copper because money is the one thing to colour; the margin because the receipt is the feature; sentence case and sans figures because nothing here is a terminal.

Three PRs, M10 steps 23 to 25, in this order. Each ships on desktop and web and keeps every test green.
