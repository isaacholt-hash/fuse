# UI review: ChatGPT and Claude against FUSE (2026-11-01)

A walk through both web apps in Isaac's signed-in Chrome, screen by screen, compared with FUSE's UI as of `main` after M10 F1. Only product patterns are recorded here, no account content.

**Looked at.** ChatGPT: home (Chat and Work), composer menus, the thinking-effort picker, a long conversation, message and chat menus, sidebar and project menus, Space, Scheduled, Customize (plugins, skills), Ctrl+K, and Settings (general, appearance, notifications, storage, personalization and its custom rules, keyboard, usage overview and analytics, data controls). Claude: home, composer menus (plus, model, effort, permission mode, project), incognito, a research conversation, header controls (rename, devices, outputs, share), sidebar item menu, Projects, Artifacts, Scheduled, Design, Customize, Settings (general, account, privacy, usage, capabilities, memory, reflect, time and focus, Claude Code), and the Code view (new session, a session, sidebar).

## Three things the review says about FUSE

1. **Auto-routing is now the default everywhere.** ChatGPT's Chat mode shows no model picker at all, only a thinking-effort pill; the model appears only in Work mode. Claude keeps model, effort and permission mode in one row under the composer. FUSE already shows more than either ("Auto → model", the rule that fired, the cost); the gap is that **effort is the one dial both apps put in the composer and FUSE hides it** in Model defaults.
2. **Both apps now surface "what is running and where".** Claude's sidebar rows carry a status badge and a device icon (this computer or cloud); its scheduled tasks are a top-level page with status chips and the device each runs on. After M10, FUSE runs unattended on HULK, but the only place that shows it is the Runs page and a sidebar badge count.
3. **Cost visibility is still FUSE's lead**, but both apps added a forecast sentence or reset timer to their usage pages, and ChatGPT added per-chat usage analytics. FUSE shows the past well and the future not at all.

## Separate areas for Chat and Code (added 2026-11-01, Isaac's request)

### What the two apps do

**ChatGPT has three areas: Chat, Work and Codex.** One icon rail on the far left is shared. Switching changes three things: the sidebar's title and its recents (Codex lists only coding tasks), the composer, and the empty-state prompt ("What's on the agenda today?", "What should we work on?", "What should we build?"). Each composer is different:

| Area | Composer controls |
| --- | --- |
| Chat | Plus menu, thinking-effort pill only (no model), dictation |
| Work | Model and effort popover, chips for Choose project, Files, Plugins, Open desktop app |
| Codex | Where it runs (Cloud, or Choose environment), an "Ask for approval" permission pill, model with nine effort levels, plus menu |

A conversation belongs to one area. Projects, scheduled tasks, plugins and settings are shared; the Notifications and Personalization settings have a Codex row beside the ChatGPT row.

**Claude has two areas: Chat and Code,** toggled by two icons in the sidebar header. The Code sidebar keeps Search, Artifacts, Scheduled and Customize, adds Dispatch, and its recents are sessions, each with a place icon (this computer or cloud) and a state glyph; it has its own settings gear. The Code composer reads "Describe a task or ask a question" with an environment picker (Default cloud, or choose), a Repo picker, model, effort and the Auto permission mode. A session has a right rail: Environment (remote control, repository, branch), a context meter in percent, and Outputs. "Edited N files" cards carry the plus and minus counts, Undo and See all. Settings are one modal for both areas, with a Claude Code section.

**Common to both:** one account, projects and search span the areas; the switch is one click, persistent, and each area reopens on its own last item; rows in the code area say where the work runs; the code composer leads with where and how (environment, repository, permission), the chat composer with effort.

### FUSE today

One surface. Code and Work are toggles in the composer, set per message, with the run permission select, New branch and Run on HULK beside them. A thread can mix chat turns and runs; runs show as cards inside the thread; the Runs page lists runs across threads; projects carry the repository and folders.

### Proposal: two areas, Chat and Code

**The switch.** A segmented control in the sidebar header, Chat | Code, with Ctrl+1 and Ctrl+2. The app reopens in the last area and on that area's last item (CH-10). Under 600 px it becomes a bottom tab bar.

**Chat area.** Today's sidebar without the Runs footer button. The composer loses the Code and Work toggles, the run permission select, New branch and Run on HULK. It keeps attach, web search, the effort dial (item 5), compare, the model picker and the context meter. A chat can still read a project's folders and repository (CA-01, WF-03) but cannot change them; when a message asks for an edit, the routing-suggestion banner FUSE already has offers "Continue in Code".

**Code area.** Sessions, of kind Code or Work. The sidebar: New session; Search over sessions; a state filter row (Going, Waiting for you, Done) that replaces the Runs page; Scheduled (item 3); then sessions grouped by project or repository, each row with the state dot, the place icon (this computer, HULK) and the kind glyph (item 1). The new-session screen reads "Describe a task" and leads with where and how, in this order: Project or repository (required), Where (This computer, HULK; greyed with the reason when a folder is only on one machine, PL-02), Mode (Read-only, Ask first, Can edit files), Branch (new, named after the task, or current), Kind (Code, Work), Model (Auto → model, with effort), Cost cap. Below it, sessions waiting for you and the next scheduled tasks. The session view gets the environment strip (item 20) under the header, run cards opened to their steps by default, a Files panel on the right (changed files with diff and Undo, outputs, artifacts), and a composer that reads "Reply, or type / for commands" with Stop.

**Handoff both ways.** "Continue in Code" from a chat creates a session in the same project seeded with the thread summary and the last messages (PM-06 summary, not the whole thread). "Discuss in Chat" from a session opens a chat seeded with the session's summary and the files it changed. Both are recorded as a link between the two threads so each shows the other.

**Shared.** Projects, memory, search (Ctrl+K palette searches both, item 12), artifacts, scheduled tasks, usage and settings. Settings gains a Code section (default mode per project, run cards view, HULK pairing, sandbox, agent audit) in the navigation from item 7. Usage splits by area (item 16). Routing, egress and the request log are unchanged (CA-09); the cost cap and spend so far move into the session header where they are read most.

**Data.** `threads.kind` (chat, code, work), one forward-only migration. Existing threads that hold a run become the kind of their last run; the rest stay chat. Nothing is split or moved; a mixed thread opens in the Code area with its chat turns intact.

**Why two areas and not three.** Code and Work sessions share the runner, approvals, diffs and undo, the cost cap and the HULK handover; what differs is the folder and the tools, which is one chip. Two tabs are easier to keep in the head than three, and Work sessions get the same status and place signals for free. The alternative is ChatGPT's shape, Chat | Code | Work, which costs a third sidebar and composer; it would make sense only if Work sessions become as frequent as Code ones.

**Size: L, three PRs.** (1) The `kind` column, the area switch, the filtered sidebars and empty states, with the current composer unchanged. (2) The Code new-session screen, the slimmed Chat composer, the environment strip and the Files panel. (3) Handoff both ways, the Runs page folded into the Code sidebar, Usage by area.

**Decided (Isaac, 2026-11-01):** two areas, Work sessions inside Code, on desktop and web alike. Queued as M10 steps 12, 16 and 17, with steps 13 to 15 built inside the Code area.
